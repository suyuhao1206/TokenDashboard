## A. 确凿 Bug（建议按顺序修）

### A1. 扫描完成的 toast 文案与实际不符 🐛

- **位置**：`ui/index.html` L904-905（`refresh("scan")` 分支）
- **现状**：
  ```js
  const n = (res.events || 0) + (res.channel_rows || 0);
  toast(n > 0 ? `扫描完成：新增 ${fmt(res.events)} 条事件` : "扫描完成：没有新的日志");
  ```
- **问题**：判断条件 `n` 包含了 `channel_rows`，但文案只报 `events`。
  当 events=0、channel_rows>0 时，会提示「新增 0 条事件」——看起来像没扫到。
- **修法**：文案把两个数都带上：
  ```js
  toast(n > 0
    ? `扫描完成：新增 ${fmt(res.events)} 条事件 · ${fmt(res.channel_rows)} 行渠道数据`
    : "扫描完成：没有新的日志");
  ```
- **验证**：面板点「⟳ 扫描」，观察 toast 数字与 CLI `scan` 输出一致。

### A2. CLI 渠道行输出有多余尾巴 🐛

- **位置**：`cli.py` L22-25（`cmd_scan`）
- **现状**：渠道分支固定拼 `f" | {stats.get('note', '')}"`，note 为空时行尾多一个 `" | "`；
  而下面的 harness 分支用了条件拼接的 `note` 变量，两种写法不一致。
- **修法**：渠道分支也先算 `note = f" | {stats['note']}" if stats.get("note") else ""`，再拼。
- **验证**：`uv run token-dashboard scan`，渠道行 note 为空时行尾干净。

### A3. `run_widget` 高度兜底值与默认值不一致 🐛

- **位置**：`widget_web.py` L456
- **现状**：`h = int(state.get("height") or 210)`，但 `WIDGET_DEFAULTS["height"]` 是 246。
  state 里 height 为 None/0 时拿到 210，和默认尺寸对不上。
- **修法**：`h = int(state.get("height") or WIDGET_DEFAULTS["height"])`。
- **顺带**：`fit_viewport` 里 clamp 用 `(160, 140)`，`create_window(min_size=(180, 160))`
  用另一组值，统一成同一对常量（比如都取 min_size）。
- **验证**：删掉 `config/widget-web.json` 后启动 widget，窗口尺寸 = 246 高。

### A4. `--port 0` / `port or` 陷阱 🐛

- **位置**：`server.py` L159；`widget_web.py` L135
- **现状**：`port = port or int(srv.get("port", 8787))` —— 显式传 `0`（让系统分配随机端口）
  会被 `or` 吞掉回退到 8787。
- **修法**：`port = port if port is not None else int(srv.get("port", 8787))`。
- **验证**：`uv run token-dashboard serve --port 0` 应打印随机端口而不是 8787。
  （优先级低，但属于经典 Python 坑，顺手改掉。）

### A5. 复用端口时不校验对方身份 🐛

- **位置**：`widget_web.py` `_api_ok()`
- **现状**：8787 上任何返回 200 的 HTTP 服务都会被当成「已有面板进程」直接复用。
  如果本地另一个开发服务恰好占了 8787 且 `/api/meta` 返回 200（哪怕是 404 页面的 200），
  widget 会连错服务、页面全空。
- **修法**：校验响应体特征：
  ```python
  data = json.loads(r.read())
  return r.status == 200 and "harnesses" in data and "min_date" in data
  ```
  或者更正式一点：给 FastAPI 加 `/api/version` 返回 `{"app": "token-dashboard", "version": ...}`，`_api_ok` 认这个。
- **验证**：用 `python -m http.server 8787` 占端口后启动 widget，应报「端口被占用」而不是静默复用。

### A6. 会话表的 `MAX(project)` 取值不确定 🐛

- **位置**：`db.py` `sessions()` L288
- **现状**：`MAX(project)` 对字符串取的是**字母序最大**，不是「最近使用的项目」。
  跨目录的会话（同一个 session_id 换了 cwd）项目名显示哪个纯看字母运气。
- **修法**（二选一）：
  1. 简单：`GROUP_CONCAT(DISTINCT project)` 展示全部项目（前端截断显示）；
  2. 准确：子查询取 `ts` 最大那行的 project：
     ```sql
     (SELECT project FROM usage_events e2
      WHERE e2.session_id = e.session_id ORDER BY ts DESC LIMIT 1) AS project
     ```
- **验证**：构造/找一个跨项目会话，确认显示的是最后活跃的项目。

### A7. 会话明细与日报口径不一致（local_date NULL） 🐛

- **位置**：`db.py` `sessions()` L293 `WHERE 1=1{frag}` vs `daily_report()` 等 `WHERE local_date IS NOT NULL`
- **现状**：时间戳解析失败的事件（`ts=""` / `local_date=None`）会出现在会话明细里，
  但任何日报/KPI/热力图都不含它——两个面板区块对不上账。
- **修法**（二选一，推荐 1）：
  1. 入库侧拦截：各 collector 在 `dt is None` 时跳过该事件（并计入 `errors`），
     从源头杜绝无时间戳事件；
  2. 查询侧对齐：`sessions()` 也加 `AND local_date IS NOT NULL`。
- **验证**：`SELECT COUNT(*) FROM usage_events WHERE local_date IS NULL;` 应为 0。

### A8. 日期筛选没有 since ≤ until 校验 🐛

- **位置**：`ui/index.html` `bind()` 里 `fSince` / `fUntil` 的 onchange
- **现状**：用户把「从」选得比「到」晚，所有图表静默变空，无任何提示，看起来像坏了。
- **修法**：onchange 里校验：
  ```js
  if (state.since && state.until && state.since > state.until) {
    // 方案 a：自动互换；方案 b：toast 提示并恢复原值
    [state.since, state.until] = [state.until, state.since];
    document.getElementById("fSince").value = state.since;
    document.getElementById("fUntil").value = state.until;
    toast("起止日期已自动互换");
  }
  ```
- **验证**：从 10-20 到 10-01，应自动互换或提示，而不是空白。

### A9. widget 按 Esc 直接退出，容易误触 🐛

- **位置**：`ui/widget.html` L322-324
- **现状**：`if (e.key === "Escape") call("quit")` —— 无边框小窗里 Esc 是高频误按键，
  一按进程就没了（有托盘还好，`--no-tray` 时就彻底没了）。
- **修法**：二次确认式退出：
  ```js
  let escArmed = false;
  if (e.key === "Escape") {
    if (escArmed) { call("quit"); return; }
    escArmed = true; toast("再按一次 Esc 退出");
    setTimeout(() => escArmed = false, 2000);
  }
  ```
- **验证**：按一次 Esc 只提示，2 秒内再按才退出。

### A10. 热力图月份标签可能重叠 🐛

- **位置**：`ui/index.html` L660-668（`renderHeatmap` 月份标签）
- **现状**：每月标签 `span 3`，如果相邻两个月的「周首列」相距不到 3 列
  （月初在周六/日时会连续出现），两个「X月」会叠在一起。
- **修法**：记录上一个标签的列号，距离太近就跳过：
  ```js
  let prevMonth = -1, prevCol = -10;
  // 循环内：
  if (first.getMonth() !== prevMonth && c - prevCol >= 4) {
    mhtml += ...; prevMonth = first.getMonth(); prevCol = c;
  }
  ```
- **验证**：看跨年/连续短月的边界（如 1 月末~3 月初）标签不重叠。

### A11. toast 1.6 秒偏短 🐛

- **位置**：`ui/shared.js` `toast()` L122
- **现状**：`setTimeout(..., 1600)`，长一点的消息（如扫描结果）还没读完就消失了。
- **修法**：按时长随字数缩放：`setTimeout(..., Math.max(2000, msg.length * 90))`。
- **验证**：触发扫描 toast，能从容读完。

## B. 待核实（可能是真 bug，先验证再改）

### B1. reasoning_tokens 可能被重复计入总量与成本 ⚠️（最重要的一条）

- **位置**：
  - `collectors/codex.py` L142-146（`o` 与 `rr` 分别取自 `output_tokens` 和 `reasoning_output_tokens`）
  - `collectors/workbuddy.py` L101-107（`completion_tokens` 与 `reasoning_tokens`）
  - `db.py` `_TOKENS = input + cache_read + cache_write + output + reasoning`
  - `pricing.py` L114：`("output", output_tokens + reasoning)`
- **疑点**：OpenAI 系 API 的口径里，`completion_tokens`（以及 Codex 的 `output_tokens`）
  **通常已经包含** reasoning 部分。如果是这样：
  - `_TOKENS` 把 reasoning 又加了一遍 → 总量虚高；
  - `pricing.cost` 里 `output + reasoning` 乘输出费率 → 成本双算。
- **但**：README 记录与 ccusage 逐日核对 57 天中 54 天完全一致，说明要么 ccusage 同样这么算，
  要么这两个字段实测互不重叠。**所以不能直接改，先核实**。
- **核实步骤**：
  1. 找一个含 reasoning 的 Codex 会话文件：`grep -l reasoning_output_tokens ~/.codex/sessions/**/*.jsonl | head -1`；
  2. 看相邻几条 `token_usage_record`，确认 `output_tokens` 是否 ≥ `reasoning_output_tokens`
     且差值是否合理（若 output == reasoning + 文本输出，则包含；若 output 与 reasoning 各自独立增长，则不重叠）；
  3. 同样检查 WorkBuddy 的 `rawUsage.completion_tokens` vs `completion_tokens_details.reasoning_tokens`（OpenAI 官方文档明确 completion_tokens 含 reasoning）。
- **若确认重叠**，修法（二选一）：
  - 入库时拆分：`output_tokens = o - rr`（存「纯文本输出」），其余逻辑不动；
  - 或 `_TOKENS` 去掉 `+ reasoning_tokens`、`pricing.cost` 只用 `output_tokens`（存「含推理的输出」）。
  - 推荐前者：报表里「输出」「推理」两列语义更清晰。
- **验证**：改完后用 `_reprice` 同款逻辑重算（`update-pricing`），
  与 `npx ccusage codex daily` 再对一天账。

## C. UI / UX 提升任务（按价值排序）

### C1. KPI 卡不跟随筛选，容易误解 ⭐ 高价值

- **现象**：选了日期范围 / harness 后，5 张 KPI 卡（今日/近7天/近30天）纹丝不动，
  只有状态条 chip 和图表变。用户第一反应是「筛选没生效」。
- **方案**（推荐 a）：
  a. 有筛选时，把 hero 第一张卡换成「所选范围」（数据用 `/api/summary` 已返回的 `s.range`），
     或在 5 卡前插入第 6 张「所选范围」卡（accent 描边区分）；
  b. 退而求其次：筛选激活时给 hero 区整体加一层说明角标「KPI 卡为固定窗口，不随筛选变化」。
- **涉及**：`ui/index.html` `heroCards()`、`statusBar()`；无需改后端（`range` 已有）。
- **验证**：选「近 7 天」+ 某个 harness，hero 区有明确的范围数据反馈。

### C2. 图表首次加载无占位 ⭐

- **现象**：骨架屏只覆盖了 KPI 卡（`.sk-line`），四张图表区首载时是空白，
  慢磁盘/首次启动时有几秒「页面像没加载完」。
- **修法**：`.chartbox` 初始加 `is-loading` class，CSS 里复用 shimmer 动画做整块骨架；
  数据到达后（`renderDailyChart` 等处）移除。空数据的 `is-empty` 逻辑不变。
- **涉及**：`ui/index.html` 的 `<style>` + 4 个 render 函数入口。
- **验证**：DevTools 节流传 Slow 3G 刷新，图表区有骨架而不是纯白。

### C3. 最近请求表支持点击表头排序 ⭐

- **修法**：后端 `GET /api/requests` 加 `sort` 参数（白名单：`ts`/`total`/`cost`，
  `total` 用 `_TOKENS` 表达式），`ORDER BY` 换掉硬编码的 `ts DESC, id DESC`；
  前端表头加 `data-sort` + 点击切换 asc/desc，当前排序列显示 ▲/▼。
- **注意**：`sort` 必须走白名单映射，不能拼用户输入进 SQL。
- **涉及**：`server.py` requests()、`db.py` recent_requests()、`index.html` 表头与 `loadRequests()`。
- **验证**：点「成本」表头，最贵的请求在最上；再点一次倒序。

### C4. 请求表加模型筛选 / 搜索

- **修法**：
  1. `/api/meta` 增加 `models` 列表（`SELECT DISTINCT model ...`）；
  2. `/api/requests` 加 `model` 参数（`_filter` 已支持 harness，照抄一个 model 分支）；
  3. 前端筛选条加「模型」下拉（选项从 meta 来），`qs()` 带上即可。
- **价值**：排查「那个最贵的模型到底谁在调」时不用一页页翻。
- **验证**：选某模型后表格总数变化、翻页正常。

### C5. 加载失败给「重试」按钮

- **现象**：`refresh()` catch 里只改了文案，用户只能手动点刷新。
- **修法**：失败时在 statusbar 的 chip 里渲染一个 `<button onclick="refresh('manual')">重试</button>`；
  同时把「数据范围 ~ 更新于」行的错误文案也带重试链接。
- **验证**：停掉服务后刷新面板，出现重试按钮；起服务点重试恢复。

### C6. 渠道视图联动与渠道筛选

- **现状**：`/api/meta` 已返回 `channels`，但面板没有渠道维度筛选；
  渠道表也不随顶部日期筛选变化（后端 `channel_summary` 支持 since/until，前端 `qs()` 已带上——
  这部分其实已经联动了，缺的只是**渠道筛选器**和**渠道区块也加个趋势图**）。
- **修法**（可分两步）：
  1. 渠道表格上方加渠道多选（或单选下拉），过滤表格行（纯前端即可，数据都在）；
  2. 进阶：`/api/channels` 的 `daily` 数据画一张按渠道堆叠的面积图放进渠道区块。
- **验证**：渠道多时筛选定位；趋势图与表格总数对得上。

### C7. widget 右键菜单显示状态 + 自启入口

- **修法**：
  1. 「置顶」菜单项前加勾选标记：打开菜单时根据 `state.top` 渲染 `✓ 置顶` / `⇧ 置顶`
     （现在点了之后只有 toast，菜单里看不出当前状态）；
  2. 加「开机自启」项：调一个新桥方法 `set_autostart(on)`，
     后端用 `winreg` 写 `HKCU\...\Run` 或创建启动文件夹快捷方式
     （逻辑可复用 `install-autostart.cmd` 的思路，Python 实现）；
     菜单同样显示勾选状态。
- **涉及**：`ui/widget.html` 菜单渲染、`widget_web.py` `Api` 类。
- **验证**：切置顶后重开菜单有 ✓；开自启后 `shell:startup` 里有快捷方式。

### C8. widget 迷你柱点击跳面板对应日期

- **修法**：柱子加 `data-date`，点击时 `call("open_panel")` 的进阶版——
  面板 URL 支持 hash 参数（如 `/#since=2026-10-15&until=2026-10-15`），
  `open_panel` 拼 URL，面板启动时读 hash 初始化 `state.since/until`。
- **涉及**：`widget.html` renderSpark、`widget_web.py` open_panel、`index.html` 启动段。
- **验证**：点上周三的柱子，浏览器打开面板且已筛选到那天。

### C9. 主题按钮图标跟随状态

- **现状**：`applyTheme()` 把按钮文案改成「浅色/深色」，但初始 HTML 是「◐ 主题」，
  首次加载闪烁一下文案变化；且「浅色」二字是状态还是动作有歧义。
- **修法**：统一为「图标 + 当前状态」：`☀ 浅色` / `☾ 深色`，初始 HTML 直接写成
  `<button id="btnTheme">…</button>` 留空由 JS 填，避免闪变。
- **验证**：开页面按钮立即显示正确状态，无文案跳变。

### C10. 移动端窄屏隐藏低优先列

- **修法**：`@media (max-width: 620px)` 下给请求表的「缓存写」「推理」列
  加 `display: none`（th/td 用 `:nth-child` 或加 class）。
  表格已有 `.tablewrap.x` 横向滚动兜底，此条优先级低。
- **验证**：手机宽度（DevTools 375px）下表格不需要横滚即可读。

### C11. 预算提醒（对接 M4 路线图）

- **修法**：
  1. `config.yaml` 加 `budget: {monthly_usd: 100}`；
  2. `/api/summary` 返回里加 `month_cost`（本月 1 号至今的 `SUM(cost_usd)`）；
  3. 前端状态条加预算 chip：用量 <80% 绿色，80-100%  amber，超支红色 + 累计成本卡变 warn。
- **验证**：把预算临时改成 $0.01，面板立刻全线告警。

### C12. 导出 CSV（对接 M4 路线图）

- **修法**：`/api/requests` 加 `format=csv`：复用现有查询，去掉 LIMIT，
  用 `StreamingResponse` + `csv` 模块输出；前端请求表面板右上角加「导出」按钮，
  `window.open("/api/requests?format=csv&" + qs())`。
- **验证**：导出的 CSV 用 Excel 打开无乱码（记得写 BOM：`utf-8-sig`）、行数与面板总数一致。

## D. 发布方案：GitHub Release 开箱即用版（新任务包）

> **目标体验**：用户在 GitHub Release 下载 `TokenDashboard-vX.Y.Z-windows-x64.zip`
> → 解压到任意目录 → 双击 `TokenWidget.exe` → 浮窗出现、面板可用、
> **开机自启已默认开启**（且可一键关闭）。全程不需要装 Python/uv/任何依赖。
>
> **现状盘点**：spec 双产物链路已成熟（`build_exe.ps1` + 两个 `.spec`），
> `_builtin_defaults` 保证无 config.yaml 也能跑，litellm 价格表已打进 exe，
> GitHub 仓库已存在（`suyuhao1206/TokenDashboard`）。**缺的只有四块**：
> CI 自动构建发版、版本号注入、首启自注册开机自启、发布物 hygiene。

### D0. ⚠️ 红线：发布物绝不能从本机 `dist/` 打

- **现状**：本机 `dist/data/` 里有 `usage.db`（你的全部真实用量）、`widget.log`、
  WebView2 profile。`.gitignore` 已排除它们进 git，但 **zip 是文件层面的事，与 git 无关**。
- **规则**：发布 zip **只在 CI 全新构建产物上打包**，或本地打包时用脚本显式只收
  `TokenWidget.exe` + `TokenDashboard.exe` + 说明文件，白名单制，不做「拷贝整个 dist」。

### D1. GitHub Actions：打 tag 自动构建并发 Release ⭐ 核心

- **新建** `.github/workflows/release.yml`，触发条件 `push: tags: ["v*"]`：
  ```yaml
  name: release
  on:
    push:
      tags: ["v*"]
  jobs:
    build:
      runs-on: windows-latest
      steps:
        - uses: actions/checkout@v4
        - uses: astral-sh/setup-uv@v5          # 装 uv
        - uses: actions/setup-python@v5
          with: { python-version: "3.12" }
        - run: uv sync
        - name: 注入版本号（见 D2）
          run: python packaging/bump_version.py ${{ github.ref_name }}
        - run: uv run pyinstaller --noconfirm --clean TokenWidget.spec
        - run: uv run pyinstaller --noconfirm --clean TokenDashboard.spec
        - name: 冒烟测试（见 D4）
          run: .\dist\TokenDashboard.exe report
        - name: 打 zip（白名单：只收两个 exe + 上手说明）
          run: |
            mkdir stage
            copy dist\TokenWidget.exe stage\
            copy dist\TokenDashboard.exe stage\
            copy packaging\快速上手.txt stage\
            Compress-Archive stage\* "TokenDashboard-${{ github.ref_name }}-windows-x64.zip"
        - uses: softprops/action-gh-release@v2   # 自动建 Release 并挂 zip
          with:
            files: TokenDashboard-*.zip
  ```
- **要点**：
  - spec 里 `upx=True`：CI 上没装 UPX 时 PyInstaller 会告警并跳过（不致命），
    建议显式装 UPX（`choco install upx`）或把 spec 改成 `upx=False` 求稳；
  - 构建机路径是纯 ASCII，**不会触发**中文路径兼容层，但兼容层代码必须保留
    （用户机器上中文路径是常态，这正是它的价值）；
  - `tzdata` 已收进 spec，CI 不用额外处理时区库。
- **验证**：本地先手动跑一遍三条 pyinstaller 命令确认绿；然后 `git tag v0.2.0 && git push --tags`，
  等 Action 跑完，从 Release 下载 zip 到**另一台机器或虚拟机**双击验证。

### D2. 版本号单一来源 + 注入

- **现状**：`pyproject.toml` 里是 `0.1.0`，exe 和面板都不知道版本。
- **修法**：
  1. `src/token_dashboard/__init__.py` 加 `__version__ = "0.1.0"`；
  2. 新建 `packaging/bump_version.py`：接收 tag（如 `v0.2.0`），
     同步改写 `pyproject.toml` 与 `__init__.py` 里的版本号；
  3. `server.py` 加 `/api/version` 返回 `{"app": "token-dashboard", "version": __version__}`
     —— 顺手解决 **A5**（widget 复用端口时认这个接口验身份）；
  4. 面板页脚/页头副标题显示 `v{version}`（`/api/meta` 里带出来即可）；
  5. （可选）exe 文件属性里的版本号：PyInstaller 用 `--version-file`，
     由 bump 脚本生成 version info 文本。
- **验证**：`TokenDashboard.exe report` 正常；`curl http://127.0.0.1:8787/api/version` 返回 tag 版本。

### D3. 默认开机自启：首启自注册 + 可一键关闭 ⭐ 需求核心

- **设计决策**：不写安装器（见 D6 为什么暂不做），改为 **widget 首次启动时自己注册**。
  理由：用户拿到的是绿色 zip 没有安装环节，「默认自启」只能在首启时落地。
- **修法**（`widget_web.py`）：
  1. `config.py` `_builtin_defaults` 的 `widget` 段加 `"autostart": True`；
  2. 新增两个函数：
     ```python
     def _autostart_lnk() -> Path:
         startup = Path(os.environ["APPDATA"]) / r"Microsoft\Windows\Start Menu\Programs\Startup"
         return startup / "TokenWidget.lnk"

     def set_autostart(on: bool) -> bool:
         """创建/删除启动文件夹快捷方式。复用 install-autostart.cmd 的 COM 思路，
         但用 Python 直接调（不弹 cmd 窗口）。
         打包后 sys.executable 就是 TokenWidget.exe 自身。"""
         lnk = _autostart_lnk()
         if on:
             import pythoncom, win32com.client  # 或 ctypes 调 IShellLink
             shell = win32com.client.Dispatch("WScript.Shell")
             sc = shell.CreateShortCut(str(lnk))
             sc.TargetPath = sys.executable
             sc.WorkingDirectory = str(Path(sys.executable).parent)
             sc.save()
         else:
             lnk.unlink(missing_ok=True)
     ```
     （`pywin32` 需要加进依赖并写进 spec 的 hiddenimports；不想加依赖就用
     `subprocess` 调一行 PowerShell 创建快捷方式，效果一样、零新依赖，推荐后者。）
  3. `run_widget()` 在窗口创建前判断：
     `if wcfg.get("autostart", True) and not _autostart_lnk().exists(): set_autostart(True)`
     并 `say("已默认开启开机自启（右键菜单可关闭）")`；
  4. `Api` 类暴露 `set_autostart(on)` 桥方法，`get_state` 里带上 `autostart` 状态；
  5. `widget.html` 右键菜单加「✓ 开机自启」项（勾选态显示，配合 **C7** 的菜单状态任务一起做）；
  6. 快捷方式只认 exe 当前位置：用户移动文件夹后快捷方式会失效——
     每次启动时检查 lnk 的 TargetPath 是否等于当前 `sys.executable`，不等就重建。
- **注意分寸**：默认开启自启是侵入性操作，首启必须**可见地告知**
  （widget 状态条显示一句 + `widget.log` 记录），且菜单一键可关。不要静默注册。
- **验证**：删快捷方式 → 双击 exe → 启动文件夹出现 `TokenWidget.lnk`；
  菜单关掉自启 → lnk 消失；移动 exe 目录后重启 → 快捷方式指向新位置。

### D4. CI 冒烟测试（防「构建绿了但 exe 起不来」）

- **修法**：workflow 里构建后跑：
  ```powershell
  .\dist\TokenDashboard.exe --help            # 进程能起、入口正常
  .\dist\TokenDashboard.exe report            # 空库不崩（CI 上无任何日志数据）
  ```
- **不测**：`TokenWidget.exe` 是 GUI，CI 无桌面会话起不来——
  这就是为什么 README 里「打包后务必实机双击验证」那条要保留在发布 checklist 里。
- **进阶（可选）**：加 `--version` 子命令，CI 断言输出等于 tag 名，版本注入错了能当场抓住。

### D5. 发布物内容与上手文档

- **zip 内容（白名单）**：
  ```
  TokenWidget.exe        # 双击即用（浮窗+内嵌面板）
  TokenDashboard.exe     # 命令行（scan/report/serve/update-pricing）
  快速上手.txt            # 3 行：双击哪个、面板地址、自启怎么关
  ```
- **新建** `packaging/快速上手.txt`，内容极简化：
  ```
  1. 双击 TokenWidget.exe，右下角出现浮窗即成功（首次会被 SmartScreen 拦：
     点「更多信息」→「仍要运行」，未签名软件的正常提示）。
  2. 浏览器打开 http://127.0.0.1:8787 看完整面板。
  3. 默认已开启开机自启；关闭：右键浮窗 → 取消「开机自启」。
  ```
- **README 加下载区**：顶部放 Release 徽章 +「下载 → 解压 → 双击」三步说明。
- **杀毒/SmartScreen 说明**：未签名 PyInstaller exe 被 SmartScreen 提示是
  **必然事件**（不是 bug），写进 README FAQ；预算充足可买 OV 代码签名证书（进阶，非必须）。

### D6. （可选进阶）Inno Setup 安装器

- **何时需要**：用户反馈「zip 解压不知道放哪 / 想要开始菜单入口 / 卸载不干净」时再做。
- **路线**：Inno Setup 脚本 → 安装到 `%LOCALAPPDATA%\Programs\TokenDashboard`
  → 安装器写自启注册表项（比快捷方式更标准）→ 卸载时清注册项（data/ 保留并提示）。
- **现阶段不建议**：多一层构建复杂度，绿色 zip 对目标用户（开发者）完全够用。
