## A. Bug 与待验证项（按优先级）

### A0. 浮窗标题栏无法拖动 ✅ 已于本日修复（补充条目）

- **现象**：拖标题栏窗口不动，其他桥调用（置顶/退出/打开面板）正常。
- **根因**：`Api.begin_drag()` 用 `ReleaseCapture + SendMessageW(WM_NCLBUTTONDOWN, HTCAPTION)`
  伪装系统拖动，但 pywebview 的 `util.js_bridge_call` 明确写着「The function is executed
  in a separate thread to prevent blocking the UI thread」——js_api 在**独立工作线程**执行。
  系统移动循环依赖触发线程的按键状态，跨线程 SendMessage 伪装出来的状态不对，
  移动循环直接退出，表现就是拖不动。
- **修法（已实施）**：改用 pywebview 官方 `easy_drag` 的同款算法（见 `webview/js/customize.js`
  与 `winforms.move`），不再碰 Win32 消息：
  - `widget_web.py`：`begin_drag()` 删除，换成 `move_to(x, y)` → `self._window.move(x, y)`
    （公开 API，入参为逻辑像素，内部自动乘 `_scale` 转物理像素，DPI 安全）；
  - `widget.html`：标题栏 `mousedown` 记录 `clientX/Y`，`mousemove` 时调用
    `call("move_to", ev.screenX - cx, ev.screenY - cy)`，`mouseup` 移除监听并存位置；
    16ms 节流防止桥调用排队；按钮排除与双击打开面板行为保持不变。
- **验证**：`uv run token-dashboard widget`（或重新打包 exe）后拖标题栏应平滑移动；
  拖完重启浮窗位置正确；按钮点击、双击打开面板不受影响。
- **备注**：如果以后想再省代码，也可以直接 `easy_drag=True` 并把标题栏加上
  `pywebview-drag-region` class（或 `webview.settings['DRAG_REGION_SELECTOR'] = '#titlebar'`），
  这是官方支持的拖动区域用法；当前实现保留了「按在按钮上不拖动」的精细控制。

### A1. 「所选范围」卡的「较前一周期」预设范围恒为「-」，自定义范围窗口错位 ⭐ 本轮最重要

- **位置**：`ui/index.html` `heroCards()` L891-895
  ```js
  const d = new Date((state.until || (meta ? meta.max_date : "")) + "T12:00:00");
  const span = Math.max(1, daysBetween(state.since, state.until) + 1);
  const w1s = fmtISO(addDays(d, -span)), w1e = fmtISO(d);
  const w0s = fmtISO(addDays(d, -2 * span)), w0e = w1s;
  ```
- **问题 1（预设范围直接失效）**：`range` 为 `today / 7d / 30d` 时 `state.until` 是空字符串，
  `daysBetween(state.since, "")` 中 `new Date("T12:00:00")` 是 Invalid Date → 结果为 `NaN`，
  `Math.max(1, NaN)` 仍是 `NaN` → `addDays(d, -NaN)` 无效 → `fmtISO` 返回 `""` →
  `sumRange(rows, "", "")` 恒为 0 → `pctChange(0, 0)` 返回 `null`。
  **结论：预设范围下「较前一周期」永远显示「-」，这个功能目前等于没有。**
- **问题 2（自定义范围窗口错位）**：当前范围是 `[state.since, state.until]`，跨度 `span` 天，
  但 `w1 = [d-span, d]` 比当前范围整体前移了一天、且与 `w0` 在边界日重叠。
  例：选 10-01 ~ 10-07（7 天），`w1` 算的是 09-30 ~ 10-07（8 天，含当前范围的 6 天），
  `w0` 是 09-23 ~ 09-30。两个窗口都不是「上一周期」，环比百分比失真。
- **问题 3（基准日期错）**：预设范围时 `d` 应取「今天」，代码却取 `meta.max_date`
  （数据最后一天）。周末/隔天没数据时两者不同，窗口进一步偏移。
- **修法**：不要从 `d` 反推，直接以「当前范围」为锚、整体前移一个跨度：
  ```js
  const curStart = state.since;
  const curEnd = state.until || daysAgo(0);        // 空 until = 今天，不再用 max_date
  const span = Math.max(1, daysBetween(curStart, curEnd) + 1);
  const prevStart = fmtISO(addDays(new Date(curStart + "T12:00:00"), -span));
  const prevEnd   = fmtISO(addDays(new Date(curEnd   + "T12:00:00"), -span));
  const cur  = sumRange(yearRows, curStart, curEnd);   // 与卡片主值同口径
  const prev = sumRange(yearRows, prevStart, prevEnd); // 真正的上一周期
  ```
  `delta` 改为 `pctChange(cur.tokens, prev.tokens)`（成本同理），
  这样「较前一周期」与卡片数字严格同源。上一周期为 0 时显示「-」是合理行为，保留。
- **验证**：
  1. 选「近 7 天」：环比出现数值（此前恒为「-」）；
  2. 自定义 10-01~10-07：手算 09-24~09-30 的 tokens，与卡片环比一致；
  3. 最新数据停在 3 天前时，预设范围的环比仍按「今天」为锚，不错位。

### A2. 模型筛选不作用于 KPI 卡 / 所选范围卡 / 预算 chip ⭐

- **位置**：
  - `server.py` `/api/summary` L41-63：签名没有 `model` 参数；
  - `ui/index.html` L782：`jget("/api/summary?" + qs({harness: state.harness}))` 没带 model。
- **现状**：`daily / breakdown / sessions / requests / hourly` 都已支持 `model`，
  唯独 `summary` 没有。选了某个模型后，图表和请求表都变了，
  但 5 张 KPI 卡、所选范围卡、预算 chip 仍是全部模型的总量——同屏数字对不上账。
- **修法**（后端一行 + 前端一行，成本很低）：
  1. `summary()` 加 `model: str | None = None`，所有 `store.totals(...)` 调用补 `model=model`
     （`db.py` 的 `totals()` 已经支持该参数，不用改 SQL）；
  2. 前端改成 `jget("/api/summary?" + qs())`，让 `model/since/until/harness` 全部带上。
     `by_harness` 是后端全量返回的，不受影响的语义保持不变。
- **顺带**：A1 修完后，范围卡环比用的 `yearRows` 请求由 `qs()` 生成、已带 model，
  与 summary 一致，不需要额外处理。
- **验证**：任选一个模型，KPI「近 7 天」tokens = 请求表按该模型筛选后的合计；预算 chip 同步变化。

### A3. 统计口径仍有裂缝：部分查询没排除 `local_date IS NULL`

- **位置**：`db.py`
  - `totals()` L346 `WHERE 1=1`（KPI/预算都走它）
  - `hourly()` L439 `WHERE length(ts) >= 13`
  - `by_harness()` L327-332、`summary()` L319-325
  - `recent_requests()` / `export_requests()` 同样只有 `WHERE 1=1`
  而 `daily_report()` / `sessions()` 已有 `local_date IS NOT NULL`。
- **影响**：新库因为采集器已拦截无时间戳事件，当前实际影响为 0；
  但旧库遗留行、或以后新采集器写入 NULL 时，KPI/请求表/活跃时段会与日报再次对不上账。
- **修法**：把过滤收敛到一处——`_filter()` 的 `frag` 初始值改为 `" AND local_date IS NOT NULL"`，
  所有走 `_filter` 的查询自动统一；`by_harness()` / `summary()` 手写的 SQL 补上同样的条件。
  `hourly()` 保留 `length(ts) >= 13`（防御性格式检查）。
- **验证**：`SELECT COUNT(*) FROM usage_events WHERE local_date IS NULL;` 为 0；
  加过滤前后各区块数字不变（有旧数据时应变为一致）。

### A4. CLI 报表表头与数据列宽不齐

- **位置**：`cli.py` L50（表头）vs L66-68（数据行）
- **现状**：表头 `输出含推理:>14`、`其中推理:>11`，数据行分别是 `output:>12`、`reasoning:>9`，
  两列各错位 2 个字符，`report` 输出对不齐。
- **修法**：抽一组列宽常量（如 `W = (12, 13, 15, 13, 14, 11, 15, 10, 7)`），
  表头与数据行共用，避免下次改列名再错位。
- **验证**：`uv run token-dashboard report` 各列右对齐。

### A5. widget 空柱子的提示与行为自相矛盾

- **位置**：`ui/widget.html` L190-192 与 L328-332
- **现状**：0 值柱子加了 `void`（`cursor: default`），但 `title` 仍写「（点击打开面板）」，
  点击事件也照样触发深链。视觉暗示「不可点」，实际能点。
- **修法（推荐 a）**：
  a. 空柱子也允许点击：`void` 的 cursor 改为 `pointer`，title 改为「当天无用量 · 点击查看」；
  b. 或彻底禁用：点击处理里 `if (bar.classList.contains("void")) return;`，title 去掉点击提示。
- **验证**：悬停空柱子，指针样式、提示文案、点击结果三者一致。

### A6. CSV 导出：Excel 公式注入 + 全量导出无上限

- **位置**：`server.py` `/api/requests` 的 `format == "csv"` 分支 L149-180；`db.py` `export_requests()`。
- **问题**：
  1. 文本列（project / model / raw_model / channel / session_id）若以 `= + - @` 开头，
     Excel 会按公式解析（CSV 注入）。本机数据风险低，但你要对外发布，值得堵上；
  2. 导出不分页、无上限，`fetchall()` 全量读入再拼成一个大字符串，
     数据量上到几十万行时内存和响应都会明显吃力。
- **修法**：
  1. 导出前统一处理文本单元格：
     ```python
     def _csv_text(v):
         s = "" if v is None else str(v)
         return "'" + s if s[:1] in ("=", "+", "-", "@") else s
     ```
     仅用于文本列，数字列不动；
  2. 加保护上限（如 `EXPORT_LIMIT = 200_000`，`export_requests` 末尾 `LIMIT ?`），
     达到上限时在响应头 `X-Export-Truncated: 1` 提示，或前端 toast「请先加筛选再导出」。
- **验证**：构造 `project="=1+1"` 的测试行，导出后 Excel 显示文本而不是计算结果；
  超过上限时行为符合预期。

### A7. （可选，仅说明）活跃时段在 DST 时区下历史数据有 1 小时偏差

- **位置**：`server.py` `/api/hourly` L195
- **现状**：`offset_h` 按**当前**时间的 UTC 偏移计算，再平移全部历史数据。
  对有夏令时的时区（如 `America/New_York`），跨 DST 的历史小时会偏 1 小时；
  `Asia/Shanghai` 等整小时固定偏移时区无影响。
- **建议**：短期只在代码注释/README 注明「活跃时段对固定偏移时区精确」即可；
  真要支持，需按事件本地时间逐条换算（`ts` 转 `datetime` 后 `astimezone(tz)`），
  工作量与收益不匹配，不建议现在做。
- **验证**：默认配置下行为不变。

### A8. （实机验证项）PerMonitorV2 之后 `fit_viewport` 的单位假设需要复测

- **位置**：`widget_web.py` L493-501
- **现状**：`cur.Width/Height` 来自 `window.native`（注释自己标注为**物理像素**），
  `dw/dh` 是 **CSS 像素**差值，两者直接相加。v0.1.1 引入 PerMonitorV2 manifest 后，
  WinForms 的坐标口径可能变化，原来的「靠 3 轮迭代收敛」未必还成立。
- **任务**：在 100% / 125% / 150% / 200% 缩放下分别启动 widget，看 `data/widget.log`：
  - 「视口 #i」是否在 3 轮内收敛到目标 260×246（±1）；
  - 若振荡或不收敛，把修正量改成 `int(dw * dpr)` / `int(dh * dpr)`，或统一改用逻辑像素口径再测。
- **验证**：四种缩放下最终视口尺寸一致，日志无反复 resize。

### A9. widget 右键菜单的勾选状态可能过期

- **位置**：`ui/widget.html` L335-346（contextmenu 只调 `applyMenuState()`）
- **现状**：菜单勾选用的是缓存的 `state.top / state.autostart`。
  用户手动删了启动文件夹的 `TokenWidget.lnk`、或另一个实例改了状态，
  菜单仍显示旧勾选。
- **修法**：contextmenu 里把 `applyMenuState()` 换成 `syncState()`
  （异步函数，直接调用不 await，它内部会重新拉 `get_state` 再 `applyMenuState()`）。
- **验证**：手动删除 `TokenWidget.lnk` 后右键浮窗，「开机自启」的 ✓ 应消失。

## B. UI / UX 提升任务（新一轮，均不与上轮重复）

### B1. 模型分布图 / 模型表在「模型筛选」下退化 ⭐ 高价值

- **现象**：选了模型 X 后，`renderModelChart()` 只剩 X 一根柱、`renderModelTable()` 只剩一行，
  「分布」失去意义（和渠道趋势图忽略 harness 筛选是同一类问题）。
- **修法**：让分布类模块忽略**自身维度**的筛选：
  `renderModelChart()` 的请求改 `qs({dim: "model", harness: state.harness})`（不带 model），
  `renderModelTable()` 同理；保留日期筛选。
  或者更省事：保持现状但在标题旁加「已按模型筛选，分布无意义」的提示——不推荐，体验差。
- **验证**：选模型 X，趋势图/请求表只显示 X，模型分布仍显示全部模型，语义清晰。

### B2. 未定价引导：一键复制价格覆盖模板 ⭐ 高价值

- **现状**：状态条 chip 能列出未定价模型，但用户不知道下一步干嘛。
- **修法**：在 chip 展开的未定价清单里，每个模型后加「复制价格模板」按钮，
  点击复制如下内容并 toast 提示：
  ```yaml
  models:
    <模型名>:
      input: 0.0        # USD / 1M tokens
      output: 0.0
      cache_read: 0.0
      cache_write: 0.0
  ```
  toast 文案：「已复制。粘贴到 config/pricing.overrides.yaml 的 models: 下，
  填价格后运行 TokenDashboard.exe update-pricing」。
  复用现有 `copyText()` 即可，纯前端任务。
- **验证**：复制后粘贴到 overrides 文件、填价、`update-pricing`，chip 计数下降。

### B3. 预算未配置时给出可操作的入口

- **现状**：未设预算时 chip 只显示「未设预算」，没有下文。
- **修法（两档）**：
  - 简单：chip 可点击，toast 显示「在 config.yaml 加 budget: {monthly_usd: 100} 后重启生效」；
  - 进阶：chip 点击弹出输入框，后端加 `POST /api/config/budget`
    （只改 `budget.monthly_usd` 一个键，写回 `config/config.yaml` 并更新内存 cfg），
    立即生效无需重启。
- **验证**：未配置时点击有明确引导；进阶版填 100 后 chip 立刻显示百分比。

### B4. 热力图日期格点击 = 筛选到当天

- **现状**：widget 迷你柱已支持点击深链，面板热力图只有 tooltip，交互不对等。
- **修法**：`renderHeatmap()` 给 `.hm-cell` 加 `cursor: pointer` 与 click 委托：
  `state.range = "custom"; state.since = state.until = cell.dataset.date; syncPresets();`
  然后 `refresh("manual")`，toast「已筛选到 YYYY-MM-DD」。
- **验证**：点某天，所有区块切到当天；再点「全部」恢复。

### B5. 会话明细可展开（按天 / 按模型构成）

- **现状**：会话表只能看汇总和复制 ID，想知道「这个会话哪天烧钱最多」要去请求表慢慢翻。
- **修法**：
  1. 后端 `_filter()` 加 `session_id` 参数，`/api/requests` 与 `/api/daily` 透传；
  2. 前端会话行点击展开一行详情：内嵌一个小表（该会话按天的 tokens/成本），
     数据用 `/api/daily?dim=total&session_id=...`；
  3. 展开行内再放「查看全部请求」链接，跳请求表并带上 session 筛选。
- **验证**：展开某会话，明细合计 = 会话行合计。

### B6. 首次使用引导从 toast 升级为引导卡

- **现状**：空库只有一条「先运行 scan」的 toast，各图表仍是分散的空态。
- **修法**：`meta.min_date == null` 时，hero 区渲染一张引导卡：
  「① 双击 TokenDashboard.exe scan ② 点右上角扫描 ③ 在 config.yaml 设预算」，
  配一个「立即扫描」按钮（直接调现有 `scanNow()`）。有数据后自动消失。
- **验证**：删掉/改名 `data/usage.db` 后开面板，出现引导卡；扫描后恢复正常。

### B7. 请求表「合计」列 hover 显示五项构成

- **修法**：合计单元格加 `title`：
  `输入 X · 缓存读 X · 缓存写 X · 输出(含推理) X · 其中推理 X`，
  与「输出」列现有的 hover 风格保持一致。
- **验证**：悬停合计，五项之和 = 合计值（再次确认不双算推理）。

### B8. 键盘快捷键

- **修法**：`R` 手动刷新、`1/2/3/4` 切换 今天/近7天/近30天/全部、`Esc` 清除筛选。

  避免在日期框里打字被截获。
- **验证**：各按键生效；日期输入框内按 1 不会切范围。

### B9. 窄屏下渠道趋势图需要一句提示

- **现状**：`renderChannelChart()` 在 `innerWidth <= 680` 时直接 return，
  图表区只剩空白（连「暂无数据」都没有，因为 showEmpty 已被置为 false）。

  或在标题 `.chartnote` 里写（注意现在 note 只在宽屏填充，窄屏是空的）。
- **验证**：680px 以下渠道区有明确提示，不是空白。

### B10. 状态条「更新于 …」可点击刷新

- **现状**：手动刷新只能靠「扫描」（会触发后端扫描，偏重），
  想只刷新数据没有轻量入口。
- **修法**：给 `#lastUpd` 加 `cursor: pointer` + 点击 `refresh("manual")`，title「点击重新拉取数据」。
- **验证**：点击后各区块刷新，但不触发 `/api/scan`。

### B11. CSV 导出加「本地时间」列

- **现状**：导出只有 `时间(UTC)`，用户要心算 +8。
- **修法**：后端导出时多写一列「本地时间」，用 `parse_iso(r["ts"]).astimezone(tz)` 格式化；
  保留 UTC 列便于对账。文件名可带上当前筛选范围（如 `...-20261001-20261007.csv`）。
- **验证**：Excel 打开直接看到本地时间，与面板请求表显示一致。
